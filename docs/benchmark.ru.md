# Проверка импорта большого файла

[English](benchmark.md) · [К README](../README.ru.md)

Замер выполнен 14.09.2026: Python 3.12.13, Django 5.2.17, openpyxl 3.1.5,
Linux x86-64, SQLite на рабочей машине. Размер пакета — 500 строк.

```bash
uv sync --dev --locked
uv run python scripts/benchmark_import.py --rows 10000 100000
```

Скрипт создаёт XLSX с пятью обязательными колонками и вымышленными адресами,
изолированную временную базу и одного пользователя. Каждый импорт запускает
настоящий сервис в отдельном новом процессе. Затем тот же файл импортируется ещё раз.
Генерация файла, подготовка базы и запуск Django не входят во время импорта.
Пиковая RSS включает весь процесс импорта. Отправка писем не запускается.

| Строк | Размер XLSX, байт | Первый импорт, с | Повтор, с | Пик RSS первый / повтор, МиБ | SQL первый / повтор |
|---:|---:|---:|---:|---:|---:|
| 10 000 | 233 668 | 0,906 | 0,615 | 54,0 / 53,3 | 282 / 122 |
| 100 000 | 2 285 981 | 9,619 | 6,214 | 61,8 / 60,7 | 2 802 / 1 202 |

Создано ровно заданное количество заданий. При повторе все строки учтены как
пропущенные: новых заданий и ошибочных строк — ноль. Скрипт проверяет это утверждениями.
SQL-счётчик включает транзакции и вставку связей, а не только SELECT. Отдельный тест
проверяет, что число запросов поиска не растёт с каждой строкой внутри одного пакета.

Это отдельные локальные измерения, не гарантии скорости и не сравнение с другими
реализациями. Файл использует inline strings и короткие тексты. Таблицы shared strings,
форматирование, длинные сообщения, диск и другая БД влияют на время и память.
Openpyxl даже в read-only загружает общие строки и стили. Замер подтверждает обработку
строк ограниченными пакетами для этих входных данных, но не постоянную память для
любого XLSX. Отправка с обязательной задержкой 5–20 секунд измеряется отдельно и сюда
не входит. Скрипту нужен Linux/macOS для модуля `resource`.
